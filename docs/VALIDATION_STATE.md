# Validation state, 18 October 2026

This build passes the complete isolated GNOME Shell test with **406 assertions** plus `NOTCHY_SHELL_TEST_OK`, `NOTCHY_PREFS_TEST_OK` and `NOTCHY_TRAY_TEST_OK` (5 min 26 s); `NOTCHY_TEST_LAYOUT_ONLY`, `NOTCHY_TEST_LAUNCHER_ONLY` and `NOTCHY_TEST_AIRPODS_ONLY` pass on their own as well. The run now also fails on `St-CRITICAL` and `Clutter-CRITICAL`; the log has none, and no GJS/GObject/GTK/Mutter criticals, script failures or Python tracebacks.

`scripts/check.sh` passes: syntax, strict schema, **48 Node tests** (domain, launcher ranking, AirPods battery cache, agent sessions, side layout) and **42 Python tests** (file operations, file search including descriptor and hanging-drive regressions, AAP reader, agent hook adapter and setup, context menu entries, cover, spectrum, MCP). `scripts/pack.sh` builds the package.

## New on 18 October 2026

- **Compact notch width (fixed, cause proven).** With music playing, the closed capsule shrank from 257 px to 171 px after any hover open/close, and only the overview restored it. `applyStyle()` replaced all of the capsule's classes and dropped `notchy-wide`, which `updateCompact()` sets for cover and waveform; `close()` also folded to a width measured when the island had opened (`panelCompactWidth`). The overview happened to call `updateCompact()` afterwards. Now one function (`syncCapsuleClass`) owns the capsule's classes, the fold target is measured from the current content (`compactWidth`), a width that changes while folding is followed, the bar placeholder keeps that width, and a morph in progress is not cut short by a reposition. The capsule's parts keep their actors across MPRIS updates (no rebuild, the waveform keeps drawing). Measured in `layoutRegressions` (see TESTING.md): 20 hover cycles with the overview, rapid hovering, track change while open, HUD, toast while folding, pause, both styles, a taller bar, scale 2.
- **Thunderstorm height (fixed, cause proven).** On the first open the result list was measured before it was on the stage (144 `St-CRITICAL` "not in the stage" lines in one run), so the start list got 92 px for 150 px of rows; during the spring the footer sat at a fixed place and was clipped. The list's height is now a constraint (`max-height`: visible rows and the screen) and the page is measured once on the stage; while morphing, the page fills the surface and the list takes what is left, so the footer is inside the surface in every sampled frame.
- **Thunderstorm ranking (fixed).** „chrome“ ranked 30 files named chrome… above Google Chrome (a file prefix scored about 890, the app's word-start about 753, with no notion of type). Ranking is now type-aware with bands (exact apps, strong apps, exact commands and quicklinks, exact files, the rest, weak matches), per-type frecency caps and an explicit file mode (`datei …`, `file …`, `/…`).
- **AirPods case battery (fixed as far as the AirPods allow).** The case reports its level only while connected to a bud; otherwise AAP says disconnected and airpods-helper -1. Notchy now keeps per device and part the last valid reading with time and source, shows it greyed with its age, never as live or charging, and asks the AirPods again at most twice (15 s, 45 s) when the case is still unknown with the built-in reader.
- **AI agent indicators (new).** A session/state model, a D-Bus API (`AgentEvent`, `AgentHook`, `GetAgents`, `AgentsChanged`), `notchyctl agent …`, MCP tools `agent_status`/`agent_end`, a hook adapter for Claude Code, Codex and Antigravity with an opt-in setup that keeps existing hooks, indicators beside the notch with a layout manager that keeps the notch centred, a „+N“ overflow, popups that update in place, and settings.
- **Scroll bars over content (fixed).** The Shell lists used overlay scroll bars that covered the right end of every row (the clipboard's time and the selected row's last action, Thunderstorm's kind labels); GTK's overlay indicator did the same over the Regal's right column. The bars now take their own thin column beside the content, only while there is something to scroll (`St.ScrollView` without overlay, GTK `overlay_scrolling=False`).
- **Other bugs found and fixed:** the AirPods symbol in GNOME's centre box pushed the notch ~20 px left of the middle; the AirPods menu was rebuilt on every change (focus and clicks lost while open) — now updated in place; a late D-Bus proxy of a vanished airpods-helper could be installed, and the built-in reader kept its channel open until the proxy was ready — now a generation guard and an immediate hand-over; „airpods-helper installed“ stayed true for a daemon that was started by hand and quit; `filesearch.py` leaked the pipe's read end on every failed index query, one hanging drive could block every worker of its pool, and the helper could hang at exit — now closed on every path, one probe per drive, slow drives skipped for a minute, a stuck pool replaced, `os._exit`; `set_activity` with NaN progress stored NaN, names longer than 80 characters could not be cleared, " a" and "a" were two activities, and the expiry timer ran without activities.

## New on 17 October 2026

- **Real context menu in the Regal.** A right click opens a GTK popover at the pointer — a real Wayland popup with vertical entries, icons, separators and submenus („Konvertieren in ▸“, „Video verkleinern ▸“). Measured in the headless Shell: Mutter stacks a GTK popup in `window_group`, below the Shell's chrome, which is why an earlier popover was covered by the island. Notchy now shows the Regal's popups (menu and tooltips) as clones on top of every chrome layer while the real popup keeps the input; while a menu is open the island's tab bar lets clicks through, the menu counts as part of the island for hover, and `ShelfHold` keeps the island open. Verified with real pointer and key events: single and multiple selection (file-manager rules), Esc, click outside and click on the tab bar close only the menu, arrow keys and Enter, real clicks on entries, the work-area bounds (`regal-context-menu*.png`).
- **A stale hover fixed.** Switching to the Regal while the pointer rested on the island left Clutter's hover flag set (the island stops being reactive there), so the island no longer collapsed when the pointer left. The Regal's hover is now computed from the pointer position; a test reproduces the old behaviour (it fails without the fix). Two older tests had relied on it unknowingly and now pin the island or keep the pointer inside, as a user would.
- **Thunderstorm as a launcher** with file search through GNOME LocalSearch (helper process, bound SPARQL parameter, 140 ms debounce, overtaken searches dropped, existence/permission checks, bounded fallback), quicklinks, units, system and window commands, clipboard, snippets, emoji, categories, an action panel and recent results (`thunderstorm-*.png`). The real LocalSearch 3.11 on this machine answers the name query in 15–40 ms on a 365 000-file index; ranked (`fts:rank`) and metadata-joined queries took 0.25–3.6 s, so ranking and metadata happen in Notchy instead. GJS cannot create the pipe Tracker's endpoint writes into (`GLibUnix.open_pipe` does not return its descriptors), hence the Python helper.
- **AirPods** with a connection card as on an iPhone, battery rings, a symbol beside the notch with their controls, and settings (`airpods-*.png`). On this machine (AirPods Pro 2 USB-C, BlueZ 5.85) BlueZ reported no battery and a 12 s Bluetooth LE scan found no battery adverts from the connected AirPods (they send those only with the case opened), so the first version showed no batteries without airpods-helper. Notchy now reads connected AirPods itself over AAP; verified against the real AirPods: left/right batteries, noise control, conversation awareness and ear state arrive as the logged-in user. On the real desktop the batteries then appeared only for the first connection: the reader sent its requests without waiting for the handshake's answer and gave up after three failed channels for good. It now follows the AirPods' connection steps and keeps retrying while they are connected; four connections in a row against the real AirPods each delivered the batteries within 0.1–0.6 s. Connected AirPods also show as a symbol with a battery ring beside the notch, with their controls on a click. The daemon path is validated against a stand-in with airpods-helper's API.
